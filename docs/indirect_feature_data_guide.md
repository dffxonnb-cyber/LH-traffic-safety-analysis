# 간접 변수 데이터 우선순위 — 상세 가이드

**목적**: 교통·사고 분석에 활용할 **간접 변수(기상·환경·지형·시설 등)**용 외부 데이터를, 객관적 기준으로 우선순위를 나누고, 각 데이터의 매칭 방식·변수 생성·활용 방향을 상세히 정리한다.  
**관련 문서**: [파생변수_간접변수_계획.md](파생변수_간접변수_계획.md)

---

## 1. 객관적 중요도 판단 기준

간접 변수 후보에 대해 **“얼마나 중요한가”**를 판단할 때 아래 네 가지 기준을 사용한다. 모두 만족할수록 **객관적으로 중요도가 높다**고 본다.

| 기준 | 설명 | 구체적 예시 |
|------|------|-------------|
| **연구·실무 증거** | 교통/사고 분야에서 해당 변수와 결과(사고·통행 등) 연관이 논문·보고로 잘 정리되어 있는지 | 강수·저시정 시 사고 증가, 터널 진입·이탈 구간 사고 집중 등이 국내외 연구에서 반복 보고됨. |
| **측정·정의 명확성** | 변수 정의가 명확하고, 전국·표준 데이터로 동일하게 재현 가능한지 | 기상은 격자/관측소·시각 기준, 터널·교량은 구간·좌표 기준으로 “동일 조건이면 동일 값”이 나오도록 정의 가능. |
| **인과·맥락 명확성** | “이 조건일 때 사고/통행이 달라진다”는 메커니즘이 설명 가능한지 | 강수→노면 미끄러움·시인성 저하, 야간→가시 거리·피로, 터널→명암 적응·구간 특성 등으로 해석 가능. |
| **데이터 접근성·일관성** | API/표준 파일로 전국 동일 조건 사용 가능한지, 지역 한정·누락이 크지 않은지 | 기상청·천문연구원 API는 전국·연속 제공, 터널·교량은 공공 표준 데이터 존재. 가로등·CCTV는 지역·기관별 편차 있음. |

### 1.1 기준별 상세 설명

- **연구·실무 증거**  
  해당 변수를 넣었을 때 사고율·통행량·혼잡 등과의 연관이 **이미 실증적으로 보고된 것**인지 확인한다. 메타 분석·국가 보고서·학술 논문에서 반복적으로 언급되면 우선순위를 높게 둔다.

- **측정·정의 명확성**  
  “강수 여부”, “야간”, “터널 구간”처럼 **동일 조건이면 누가 매칭해도 같은 값**이 나오도록 정의할 수 있는지 본다. 표준 API·공식 스키마가 있으면 재현성이 높다.

- **인과·맥락 명확성**  
  변수가 **직접 원인**이 아니어도, “날씨가 나쁠 때 시인성이 떨어진다”처럼 **맥락(메커니즘)**으로 설명 가능해야 해석과 정책 연결이 쉽다.

- **데이터 접근성·일관성**  
  **전국·동일 규격**으로 제공되는지, 지역별로 누락·형식이 다른지 확인한다. API·표준 파일이 있으면 접근성과 일관성이 높다.

## 2. 객관적으로 중요도가 높은 데이터 (우선 적용 권장)

아래 세 가지는 위 네 가지 기준을 모두 충족하는 편이어서, **우선 적용**을 권장한다.

| 번호 | 데이터 | 출처 | 매칭 방식 |
|------|--------|------|-----------|
| 1 | 기상(강수·시정·기온) | 기상청 고해상도 격자조회 / 지상(AWS)기상관측 / 기상청 API 허브 | 사고/통행 발생 시각 + 해당 격자 또는 최근접 AWS 관측소로 해당 시각의 기온·강수·시정·풍속 등 매칭 |
| 2 | 일출·일몰(야간·박명) | 한국천문연구원 출몰시각정보 | 날짜 + 지역(위도/경도 또는 관측소)으로 해당 일의 일출·일몰 시각 조회 후, 사고/통행 시각과 비교 |
| 3 | 터널·교량 | 전국도로터널정보 / 전국교량표준데이터·파일데이터 | 도로 구간 또는 사고/통행 좌표와 공간 결합(구간 포함 여부, 진입·이탈 구간 판별) |

---

### 2.1 기상(강수·시정·기온)

**요약**  
사고·통행이 발생한 **시각·위치**에 대해, 해당 시각의 기온·강수·시정·풍속 등을 격자 또는 최근접 관측소 기준으로 매칭한다. 악천후·폭염·한파 등 **시간적·환경적 맥락** 변수로 활용한다.

- **생성 변수 예시:** 강수 여부(0/1), 강수량(mm), 시정(km), 저시정 플래그, 기온, 체감온도, 폭염/한파 플래그(예: 33°C 이상, -10°C 이하).
- **활용 방향:** 악천후(강수·저시정)·폭염·한파 조건별 사고 발생 확률·통행량 비교, “맑은 날 vs 악천후” 세그먼트 모델링.

**매칭 구현 시 유의점**

- **고해상도 격자(15139478)**: 500m 격자 단위. 사고/통행 좌표의 격자 코드를 산출하거나, 격자 중심 좌표와의 거리로 최근접 격자를 찾은 뒤, 해당 격자·시각의 기상값을 사용한다.
- **지상 AWS(15057084)**: 관측소 위치가 고정. 각 사고/통행 좌표에 대해 **최근접 관측소**를 선정하고, 해당 관측소의 **해당 시각** 자료를 매칭한다. 거리 가중 평균은 선택 사항.
- **시각**: 사고/통행 **발생 시각**을 API 요청 시점의 날짜·시간으로 정확히 넘겨야 한다. 시간대(UTC vs KST)와 요청 단위(시간별/일별)를 API 명세에 맞춘다.

**링크**

- 고해상도 격자: https://www.data.go.kr/data/15139478/openapi.do  
- 지상 AWS: https://www.data.go.kr/data/15057084/openapi.do  
- 기상청 API 허브: https://apihub.kma.go.kr/

### 2.2 일출·일몰(야간·박명)

**요약**  
**날짜 + 지역(위도/경도 또는 관측소)**으로 해당 일의 일출·일몰 시각을 조회한 뒤, 사고/통행 시각이 그 전후에 있는지로 야간·박명 변수를 만든다. 시인성·가시성 맥락 변수로 사용한다.

- **생성 변수 예시:** 야간(1/0), 일몰 전후 30분(1/0), 낮 길이(분), 박명 구간 플래그.
- **활용 방향:** 야간·박명 구간에서의 사고율·통행 패턴 분석, 시인성·가시성 맥락 변수로 모델에 투입.

**매칭 구현 시 유의점**

- **지역**: 위도·경도 또는 “관측소 코드”를 넣으면 해당 위치 기준 일출·일몰 시각이 나온다. 분석 단위가 격자면 격자 중심 좌표, 구역이면 대표 좌표를 사용하면 된다.
- **날짜**: 사고/통행 **발생 일자**만 있으면 되므로, 일별로 한 번 조회해 두고 같은 날짜 레코드에 모두 적용할 수 있다. 캐싱 시 유리.
- **야간 정의**: “일몰 후 ~ 일출 전”을 1로 두면 된다. 법적 야간(예: 일몰 후 30분~일출 전 30분)이 필요하면 그에 맞게 구간을 조정한다.

**링크**

- https://www.data.go.kr/data/15012688/openapi.do

### 2.3 터널·교량

**요약**  
**도로 구간 또는 사고/통행 좌표**와 터널·교량 구간을 공간 결합하여, 해당 구간 포함 여부와 진입·이탈 구간을 판별한다. 구조적 위험·전이 구간 효과 분석에 사용한다.

- **생성 변수 예시:** 터널/교량 구간 여부(1/0), 터널/교량 진입 구간(1/0), 이탈 구간(1/0), 최근접 터널/교량까지 거리(m).
- **활용 방향:** 터널·교량 구간 및 진입·이탈 전후 사고율·속도 변화 분석, 구조적 위험 구간 도출.

**매칭 구현 시 유의점**

- **공간 결합**: 터널·교량 데이터가 **선(Line)** 또는 **폴리곤**으로 제공되면, 사고/통행 **점(Point)** 또는 **도로 구간(Line)**과의 거리·포함 관계를 계산한다. 거리 임계(예: 50m 이내를 “구간 내”로 볼지)를 프로젝트에서 정한다.
- **진입·이탈**: 터널/교량 구간의 **시작·끝** 좌표와 도로 방향을 이용해, 사고 지점이 구간 직전(진입), 구간 내, 구간 직후(이탈) 중 어디인지 분류한다. 도로 네트워크가 있으면 링크 순서로 판별할 수 있다.
- **파일 형식**: 표준/파일 데이터가 Shapefile, GeoJSON, SHP 등으로 제공되므로, 좌표계(ITRF2000, WGS84 등)를 분석 데이터와 맞춘 뒤 결합한다.

**링크**

- 터널: https://www.data.go.kr/data/15025445/standard.do  
- 교량 표준: https://www.data.go.kr/data/15028196/standard.do  
- 교량 파일: https://www.data.go.kr/data/15081953/fileData.do

## 3. 목적에 따라 중요도가 달라지는 데이터

아래 데이터는 **분석 목적(사고 vs 혼잡 vs 정책)**과 **데이터 확보 비용**에 따라 우선순위를 정하면 된다. 표는 요약이고, 각 항목별 상세는 이어서 기술한다.

| 번호 | 데이터 | 출처 | 매칭 방식 |
|------|--------|------|-----------|
| 4 | DEM/경사 | 국토지리정보원 수치표고모델 / DEM | 도로 구간 또는 사고/통행 좌표에 DEM 격자를 올려 고도·경사 추출 후 구간별 평균/최대 등 집계 |
| 5 | 신호등 | 전국신호등표준데이터 | 도로 구간 또는 노선과 신호등 위치 공간 결합 후 구간 길이로 나누어 밀도 산출 |
| 6 | 미세먼지 | 에어코리아 대기오염정보 / 측정소정보 | 사고/통행 시각·위치에 대해 최근접 측정소 또는 시도 평균값 매칭 |
| 7 | CCTV·가로등·보안등 | 전국CCTV표준 / 전국보안등 / Safemap / 가로등(지역) | 구간 또는 좌표 기준 반경 내 시설물 개수 집계, 구간 길이로 나누어 밀도(개/km) 산출 |

---

### 3.1 DEM/경사

**요약**  
수치표고모델(DEM)으로 격자별 고도를 구한 뒤, 도로 구간 또는 사고/통행 좌표에서 **고도·경사**를 추출하고, 구간별로 평균/최대 경사·급경사 여부·저지대 플래그 등을 만든다. 급경사·침수 취약 구간 분석에 사용한다.

- **생성 변수 예시:** 평균/최대 경사(°), 급경사 여부, 저지대·침수 취약 플래그, 곡률·굴곡 지수.
- **활용 방향:** 급경사·곡률 큰 구간 사고율 비교, 저지대+강수 결합(침수 맥락) 분석.

**매칭 구현 시 유의점**

- **DEM 해상도**: 격자 크기(예: 5m, 30m)에 따라 경사·곡률 정밀도가 달라진다. 도로 폭보다 촘촘한 격자를 쓰는 것이 좋다.
- **구간 집계**: 도로 구간을 따라 DEM 값을 샘플링한 뒤, 구간 단위로 **평균 경사**, **최대 경사**, “최대 경사 > N°”인 **급경사 플래그**를 산출한다. 저지대는 주변 배수 조건·과거 침수 이력과 결합하면 더 정확하다.
- **처리 부담**: 래스터 처리·구간별 집계가 무거우므로, 분석 지역을 잘라 쓰거나 전처리 결과를 캐싱하는 것이 좋다.

**링크**

- 수치표고모델: https://www.data.go.kr/data/15059920/fileData.do  
- DEM: https://www.data.go.kr/data/15059721/fileData.do

---

### 3.2 신호등

**요약**  
도로 구간 또는 노선과 신호등 **위치**를 공간 결합한 뒤, 구간 길이로 나누어 **신호등 밀도(개/km)**를 산출한다. 혼잡·병목·정체 위험 구간 변수로 활용한다.

- **생성 변수 예시:** 구간별 신호등 밀도(개/km), 신호등 수(절대값).
- **활용 방향:** 신호등 밀도와 혼잡·병목 빈도 관계, 정체 위험 구간 변수.

**매칭 구현 시 유의점**

- **공간 결합**: 신호등이 **점(Point)** 데이터이면, 도로 구간에 대해 “구간으로부터 N m 이내” 또는 “구간에 포함”되는 신호등 개수를 세면 된다. 버퍼 거리는 도로 폭·교차로 정의에 맞게 설정한다.
- **밀도**: 구간 길이(km)로 나눈 값이 **개/km**가 된다. 짧은 구간은 분산이 커질 수 있으므로, 최소 구간 길이를 두거나 인접 구간을 묶어서 해석할 수 있다.

**링크**

- https://www.data.go.kr/data/15028198/standard.do

---

### 3.3 미세먼지

**요약**  
사고/통행 **시각·위치**에 대해 **최근접 측정소** 또는 **시도 평균** PM10·PM2.5를 매칭한다. 사고의 직접 원인보다는 **이동·체류 수요**와 연관된 환경 맥락 변수로 본다.

- **생성 변수 예시:** PM10·PM2.5 농도, ‘나쁨’ 이상 여부(1/0).
- **활용 방향:** 미세먼지 악화 시 통행·체류 감소, 대기오염 수준별 이동 패턴·환경 맥락 분석.

**매칭 구현 시 유의점**

- **측정소**: 측정소 목록 API(15073877)로 위치를 받아 두고, 사고/통행 좌표와의 거리로 최근접 측정소를 정한다. 시도 단위 분석이면 해당 시도 평균값을 쓸 수 있다.
- **시각**: 대기오염 API는 **시간별·일별** 제공이 일반적이므로, 사고/통행 시각에 맞는 시간대 값을 매칭한다.

**링크**

- 대기오염: https://www.data.go.kr/data/15073861/openapi.do  
- 측정소: https://www.data.go.kr/data/15073877/openapi.do

### 3.4 CCTV·가로등·보안등

**요약**  
**구간 또는 좌표**를 기준으로 반경 내 CCTV·비상벨·가로등 개수를 세고, 구간 길이로 나누어 **밀도(개/km)**를 만든다. 야간 안전·취약 구간·시설 보강 후보지 도출에 활용한다. 데이터가 지역·기관별로 다르므로 “전국 동일 지표”로 쓰기엔 제약이 있다.

- **생성 변수 예시:** 반경 내 CCTV/비상벨/가로등 개수, 구간 밀도(개/km), 안전시설 부족 플래그.
- **활용 방향:** 야간 조명 밀도와 야간 사고 관계, 통행 많으나 안전시설 적은 취약 구간 도출, 시설 보강 우선 후보지 제안.

**매칭 구현 시 유의점**

- **반경**: “안전시설이 있다”고 보는 반경(예: 100m, 300m)을 정한 뒤, 구간 또는 격자 중심에서 반경 내 시설 개수를 집계한다. 구간이 길면 구간을 잘라 각 세그먼트별로 세고 평균하거나, 구간 전체에 대한 버퍼 내 개수를 쓸 수 있다.
- **CCTV**: 전국 표준 데이터가 있으나, 실제 보유·가동 현황과 차이가 있을 수 있다. 프로젝트에서 **보유 데이터(예: 20._CCTV_현황.csv)**가 있으면 그걸 우선 쓰고, 외부 데이터는 보완용으로 둘 수 있다.
- **가로등**: 전국 단위 표준이 아니라 **지자체별** 제공(서울 구별 등)이 많아, 분석 대상 지역에 한정해 사용한다.

**링크**

- CCTV: 공공데이터포털 보유 데이터 활용 시 해당 데이터셋 링크 사용. 전국 표준 예: 15075538, 15013094 (필요 시 data.go.kr에서 검색).
- 보안등: https://www.data.go.kr/data/15017320/standard.do  
- Safemap 비상벨·보안등: https://www.safemap.go.kr/opna/data/dataViewRenew.do?objtId=126  
- 가로등(예: 서울): https://www.data.go.kr/data/15128090/fileData.do, https://www.data.go.kr/data/15019598/fileData.do

## 4. 요약 및 적용 순서 제안

- **우선 적용(객관적 중요도 높음)**  
  **기상(강수·시정·기온), 일출·일몰(야간·박명), 터널·교량**  
  → 연구 증거·정의·재현성·인과 해석이 모두 타당한 편이므로, 간접 변수 도입 시 **먼저** 이 세 가지를 매칭·변수 생성하는 것을 권장한다.

- **목적에 따라 선택**  
  **DEM/경사, 신호등, 미세먼지, CCTV·가로등·보안등**  
  → 분석 목적(사고 vs 혼잡 vs 정책)과 데이터 확보·전처리 비용에 따라 우선순위를 정한다.  
  - 사고·위험 구간: DEM(급경사·침수), 터널·교량 후 신호등.  
  - 혼잡·병목: 신호등 밀도.  
  - 이동·체류·환경 맥락: 미세먼지.  
  - 야간 안전·시설 정책: CCTV·가로등·보안등(보유 데이터 우선).

**적용 순서 예시**

1. 기상 + 일출·일몰 → 시·공간 매칭 파이프라인 구축 및 야간·악천후 변수 생성  
2. 터널·교량 → 공간 결합 후 구간/진입·이탈 플래그 생성  
3. 필요 시 DEM, 신호등, 미세먼지, 시설 순으로 추가

## 부록: 공공데이터 API 활용 시 참고

- **공공데이터포털(data.go.kr)**  
  각 데이터셋 페이지에서 “활용신청” 후 **인증키**를 발급받아 API 호출에 사용한다. 일별/시간별 호출 제한이 있는 경우 캐싱·배치 요청을 권장한다.
- **기상청 API 허브(apihub.kma.go.kr)**  
  기상청 계정으로 가입 후 API 키를 발급받아 사용한다. 고해상도 격자·AWS 등 다양한 기상 API를 한 곳에서 이용할 수 있다.
- **좌표계**  
  분석 데이터와 외부 데이터의 좌표계(ITRF2000, WGS84, UTM 등)가 다르면 변환 후 공간 결합해야 한다.
